## Review decisions and practical limits

- **Manual blocks are authoritative.** The final reviewer reproduced a stale-basis branch overriding `host_blocked`. The host recipe now checks the explicit block first; bothSQLregressions and37focused/1993fulltests pass. Automatic replanning stays available for evidence-only blocks. Cost of this choice: deliberately held work requires a deliberate host unblock.
- **Recorded results and prose remain host declarations.** Source/action consistency is checked; remote success, causal entailment and generalization are not inferred. Cost if a host supplies a wrong receipt/lesson: a consistent but mistaken claim can still be stored. Use trusted connectors and independent outcome checks.
- **Local loads do not prove capacity/HA/SLOs.** Timings have no production deployment threshold; budgets bound returned context and scanned deliveries, not total retained-corpus work. Cost of assuming otherwise: database/model budgets may be underestimated. Configure workload-specific deployment limits before production rollout.
- **Archived exact evidence keeps its existing historical semantics.** A retained exact revision may support a historical lesson; mutable current claims need freshness policies and current-outcome binding. Cost of treating historical evidence as timeless truth: stale advice can remain semantically wrong despite exact provenance.
- **No paid-model quality claim.** No real-model answer/task-success study was run; the strongest scoped retrieval control matches recall. Cost of inferring an accuracy gain: deployment expectations would exceed the measured selection/consistency evidence. New paths remain opt-in.
- **Final source delivery is separate from release.** Versions/changelog/publication preparation were preserved; old clients supporting onlyschema7 rejectschema8. No published-package installation or production deployment is claimed.

A final full run also exposed a preexisting policy-fencing race using the default one-second maintenance wall budget under concurrent test load. `budget_exhausted` was a legitimate result; this test checks policy generation, not elapsed-time scheduling. Its explicit test budget is now100seconds, matching other non-timing race tests. Production default1second, pytest20second timeouts and the separate wall-budget regression remain unchanged. The26policy/wall focused cases and final1993-test suite pass.

The listed engineering results remain valid. They do not close the broader product goal. Real-model decision/task evaluation, sustained-workload investigation and demonstrated product improvements continue in the roadmap; package release remains deferred.
