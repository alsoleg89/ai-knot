# A bounded planning turn over current task memory

**Goal:** Let an always-on host assess available task evidence despite lexical mismatch, without treating acquisition as satisfied requirements or action authority.

**Evidence:** At `abe8be8`, `inspect_turn` returns `missing_context` before its replan/ready branches. `acquire_missing_context` intentionally returns candidates without changing that status. The current recipe therefore has no complete bounded path from paraphrased current facts to a persisted model proposal. Earlier reader evidence shows that source availability and correct decisions must stay distinct.

**Design choice:** Add an opt-in async host function `plan_once` beside `inspect_turn` in `examples/always_on_team.py`; keep stable library/transport APIs and the existing inspection behavior unchanged. One callback receives the current goal, original requirements, source text with visible one-based indices and host progress. It returns strict JSON with `action` (`plan`/`wait`), `next_step`, `basis` and application-owned `data`. The host validates domain data separately before effects. No tool/external connector is invoked by this function.

## Boundaries

- Require a nonempty host `trigger_key`; `None` is idle. Default `max_model_calls=0`; explicit1 permits one callback, no retry. The callback owns aggregate request/token accounting across turns/agents, as with semantic acquisition. Local reservation1 is not a provider-billing claim or an exactly-once guarantee.
- Only inspected `ready`, `replan`, or `missing_context` turns can enter. Fresh resume checks before and after claiming must preserve manual blocks, deadlines, terminal/waiting state, pending actions, another lease and due verification. Source-related blocks may be replanned after rechecking current evidence. Never send a lease token, internal source ref or work identity to the callback.
- Use existing `task_snapshot`, default8facts/12,000chars; overflow and empty evidence make no model call. Preserve the original requirement strings and missing lexical diagnostics. Full rendered input is bounded to65,536UTF8bytes. A callback timeout is explicit and below the fixed300-second lease TTL.
- A host input fingerprint includes stable trigger, goal, requirements, current exact refs/text and application progress, excluding this helper's own metadata. After claiming, recheck that a completed/failed attempt for the same input is not repeated; a fresh process sees the marker in intent progress. Host-controlled new trigger/progress/source changes permit another explicitly budgeted attempt. Crashes before persisting the marker may repeat inference; caller-owned durable metering remains necessary.
- The callback returns only `action,next_step,basis,data`. Reject duplicate/nonfinite JSON, unknown fields, invalid actions, empty/oversized next steps, invalid/duplicate/out-of-range citation indices and a `plan` with empty basis. A wait may have empty basis. The decision is private host progress, not a new shared fact or verified experience.
- Recheck the complete task snapshot and selected refs after provider I/O; reject additions/deletions/revisions/revocations/expiry/overflow observed there. Checkpoint successful plan as READY with its chosen basis, or wait as WAITING for a fixed60-second host timer. Preserve action-time guards; snapshots may change again after the read/checkpoint.
- Provider/format/context failures retain one local invocation reservation and store a sanitized failed-attempt marker when this lease is still owned and the intent remains safely plannable. Clear obsolete next-step/basis rather than leaving an executable-looking old proposal. Never clear a new manual block, unknown effect, deadline or another worker's lease. Cancellation remains cancellation after best-effort safe cleanup. No database transaction is held across the callback.
