# Incremental team-work evaluation foundation

> Native execution in the existing isolated worktree; user authorized autonomous work. No Astra. This prepares a prospective task-outcome evaluation; it is not a completed quality study or product goal.

**Goal:** Remove source-order and producer-reset confounds before evaluating real restarted team execution on new independently authored code tasks.

**Design:** Reuse the existing pure Case/Stage/Document records, strict public prompt projections and resource-limited Docker grader. New frozen JSON corpus loader verifies exact bytes, typed schema and unambiguous document paths. A study-only incremental publisher replaces only its own source records, preserves unrelated/derived memory and never edits executor intent state. Deterministic per-source timestamps and canonical namespaced-ref ordering make equal source sets yield equal rendered evidence across SQL engines.

**Alternatives:** Retrofitting the old measured study would change its method after observing results. Another flat-source toy would not exercise durable state or changed evidence. Preserve historical evidence and prepare new sources and controls independently instead. No new production API/service or paid model call is required for this foundation.

## Constraints and acceptance

- Protect original release checkout, all30 file hashes and versions; no push/release or Keychain/API access.
- Parent freezes generic loader/publisher/test hashes before opening new cases. Case author uses a fresh context and no old cases/results. Preserve first case bytes and every author repair, even before paid work.
- New corpus:3 independently authored pure-Python maintenance tasks,3stages each; source changes/deletion, current snapshots, hidden unittest contracts and references; no model/generated reference execution on the host.
- Publisher only changes `repo-observer` facts in its case slot prefix; shared facts from other actors and other tasks remain. Source deltas must make saved old refs/derived lessons stale through ordinary resume/review, while code/progress/basis/lease persist unchanged until the executor acts.
- Replay of a stage is idempotent; unchanged source identity/version/time persist. Timestamps break within-stage ties deterministically; reader time follows source ingestion by one second.
- Same set of facts renders byte-identically in any insertion order. Public prompts omit private test/reference content.
- Docker reference controls: each current reference passes its current stage; initial stub fails all9; prior-stage reference fails all6update contracts. Failures retained; fixture defects repaired transparently before any model study, never hidden or rescored after paid results.
- Full local suite including PostgreSQL and independent non-Astra source/method review; broad goal remains active. Paid multi-agent execution, quality comparisons and capacity remain future work, explicitly unfinished.
