# Growing task memory without hiding prerequisites

Researched **2026-10-28**, checkout **`53d72fbc290486060bad6c052f6c353516f43993`**. Official documentation was retrieved today; mutable documentation dates are retrieval dates, not publication dates. Paper versions are dated below. This research note contains no new model-quality/load experiment; its code observations refer to that baseline.

The subsequent [task-source profile and implementation](../task-source-performance.md) reduces full decoding of unrelated task records. It leaves the context-sufficiency, generic-growth and selected-context revalidation questions below open.

## Assessment

AI Knot already has whole-task snapshots, lexical selection, budgeted semantic selection, exact lineage, revision review and episodic consolidation. The next gap is an explicit host policy for an **accumulating admissible task corpus**, preserving conditions and uncertainty when it cannot all fit. This differs from scanning a large namespace. A smaller decoder/scan can improve the latter without proving a selected subset sufficient.

## Five mechanisms and what transfers

| Mechanism | Primary-source evidence | Fit and limit here |
|---|---|---|
| **Scoped current working set** | [LangGraph memory overview](https://docs.langchain.com/oss/python/concepts/memory) separates thread checkpoints from cross-thread stores scoped by application namespaces; semantic knowledge and semantic search are different concepts. | Exact `task_key` applicability and current-slot admission already supply this seam. Stable task/environment boundaries and actual same-slot supersession can keep active context small. Scope is not permission. Generic facts still enter every task; renaming a task to evade overflow can hide an older valid condition. No new store/framework is needed. |
| **Explicit overflow and controlled removal** | [Claude context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing) clears old tool results, can exclude named tools, reports clearing statistics and retains full client history. Removal is controlled, not proof the information is unnecessary. | `task_snapshot` already supplies all admitted whole facts or `SnapshotTooLarge`, without a prefix. Raising its explicit budget within 128 facts/65,536 characters is available. Keep overflow visible when no sufficient bounded set is known. Oldest-first deletion and automatic paid retries do not establish adequacy; characters are not model tokens. |
| **Requirement selection, then semantic fallback** | The same [memory overview](https://docs.langchain.com/oss/python/concepts/memory) treats search as an access method. AI Knot's [semantic contract](../semantic-context.md) is the primary implementation evidence here. | Reuse `select_context` lexical covered/missing requirements and `SemanticContext` paraphrase/cross-language candidates, free fitting-snapshot path, explicit call/byte caps, omissions and post-await checks. Semantic selection rejects an admitted universe over 128 candidates; it does not solve arbitrary growth. Scores and lexical coverage do not certify prerequisites or exceptions. |
| **Paged on-demand evidence** | [MemGPT v2, 2024-02-12, §2.3/§3.2](https://arxiv.org/html/2310.08560v2) pages retrieval to avoid overflowing context; its experiments also observe stopping before exhausting results. [MCP pagination, 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/server/utilities/pagination) defines opaque continuations for list operations. | Paging bounds one response, not total calls or prerequisite coverage. MCP list pagination is not a task-evidence paging contract. Existing subscription/change pages and `resync` serve delivery/recovery. Add another cursor/session only if measured tasks need browsing; retain per-page admission, aggregate budgets, explicit incompleteness and final revision review. Separate pages do not imply one consistent SQL snapshot. |
| **Grounded compaction with critical material kept exact** | [RECOMP v1, 2023-10-06](https://arxiv.org/html/2310.04408v1) separates extractive sentence selection from abstractive summaries and evaluates faithfulness and comprehensiveness separately; its small manual analysis guarantees neither universally. [Claude keep-tail compaction](https://platform.claude.com/docs/en/build-with-claude/compaction-keep-recent-turns) keeps chosen recent turns verbatim. [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction) produces opaque encrypted continuation state. | `derive_fact` records exact dependencies; episodic consolidation retains archived inputs. These enable inspectable projections, not automatic entailment or condition preservation. Evaluate concise derived notes while keeping required constraints/exceptions and current instructions whole. Recency alone cannot identify critical conditions. Provider continuation state cannot replace readable, revalidated shared facts or their ACL/revocation checks. |

These sources describe mechanisms, not comparative AI Knot accuracy. [Lost in the Middle v3, 2023-11-20](https://arxiv.org/abs/2307.03172) found position-sensitive failures on contemporary QA/key-value tasks; it motivates permuting evidence positions, not a claim about every current model or automatic gains from shorter context.

## Confirmed code boundaries

- **Different growth has different effects.** [`task_applicable` / `task_sources`](../../src/ai_knot/always_on/context.py) excludes other task labels, raw episodes and inactive facts from admission, but materializes each namespace before filtering. Other-task records and closed slot history add scan/decode work without increasing output; active generic and same-task unslotted records increase both. Same-slot publication already closes prior versions ([CAS](../../src/ai_knot/pool.py)); it does not collapse distinct conditions or unslotted append-only ingestion.
- **Planning stops at overflow.** [`plan_once`](../../examples/always_on_team.py) returns `snapshot_too_large` before its callback; it invokes neither selector nor compactor. Its post-callback whole-corpus comparison rejects observed additions/changes. Simply replacing that read with selected refs would stop detecting newly added, unselected blocking conditions. A selected-context planning path needs an explicit relevant-addition/revalidation contract; checking chosen refs alone is weaker.
- **Semantic fallback has an independent ceiling.** [`SemanticBudget` / `_acquire`](../../src/ai_knot/always_on/semantic.py) caps admitted candidates at 128 before ranking and returns `input_limit` above that. Scanning precedes the ceiling. Vector caches reduce repeat paid work, not candidate count; post-await validation checks captured sources rather than discovering every new row. This is not an unbounded semantic index.
- **Lineage checks do not automatically include prerequisite text.** [`select_context`](../../src/ai_knot/always_on/context.py) preserves whole selected facts but has no mandatory-ref parameter or semantic condition-closure rule. [`lineage_status`](../../src/ai_knot/always_on/lineage.py) checks recorded revisions/access, not preservation of negations, limits, exceptions or causal meaning. Complete review of supplied refs does not prove all necessary evidence was supplied.
- **Derivation is not corpus compaction.** [`derive_fact`](../../src/ai_knot/always_on/memory.py) appends output and leaves originals active; a same-task summary can worsen overflow. [`commit_consolidation`](../../src/ai_knot/always_on/maintenance.py) accepts only the owner's episodic inputs, closes covered episodes and records archived lineage. Raw episodes were already outside task context; this does not compact accumulated active semantic/procedural task facts.
- **Exact lineage is finite.** [`encode_roots` / `derivation_qualifiers`](../../src/ai_knot/always_on/lineage.py) bound roots and dependencies separately to 128 unique refs. Recursive summaries retain flattened roots and intermediates; repeated summarization cannot bypass that cap. Deleting archived sources invalidates descendants.

## Smallest justified investigation

Keep scan performance and context sufficiency separate. Compare existing snapshot, lexical selection and explicitly budgeted semantic fallback over the **same naturally ordered growing corpus**, including generic growth, normal slot replacements and episodic history. Preserve original task requirements. A host may designate mandatory evidence from explicit business preconditions; low similarity alone cannot declare an omitted condition unimportant. If mandatory whole facts do not fit, retain an explicit insufficient-context outcome.

Evaluate compaction separately only when selection demonstrably loses necessary information or costs too much. Keep original sources and an inspectable derived note; check material conditions, map retained claims to exact refs, preserve conflicts/unknowns and revalidate changes. This is a hypothesis, not an implemented losslessness guarantee. Destructive semantic consolidation, automatic shared summaries, hierarchical lineage changes or a new retrieval service need further evidence.

Freeze cases before outputs: old prerequisites among generic additions; negated/conditional rules split across facts; rollback/expiry constraints; conflicting/newer sources; one oversized fact; source correction/ACL withdrawal during selection; over 128 admissible candidates; repeated summaries near the lineage cap. Permute IDs/order, retain omissions/statuses and score **required-condition/source recall plus guarded next decisions** at equal aggregate context/provider budgets. Separate explicit abstention from a wrong ready/action decision. Parent work owns the concrete overflow/scan reproduction; no such result is claimed here.
