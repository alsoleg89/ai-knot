# Shared memory for independently running always-on agents

Research cutoff and retrieval date: **2026-10-27**. This is a design recommendation, not a measured accuracy claim. Sources below are first-party documentation/code or original papers. Live documentation and `main` URLs are mutable; a retrieval date is not their publication date. Paper versions and dated announcements are identified explicitly.

## Decision

Build a **bounded return packet and explicit catch-up/resync contract** on the existing SQL subscriptions and intent resume APIs. A long-lived agent needs to learn what changed while it slept, which assumptions became invalid, and which work remains unresolved before selecting context or acting. Shared semantic recall alone cannot establish that it has caught up.

Do not replace the current database, add a memory agent per worker, or adopt an entire graph framework for this slice. The promising transferable mechanisms are small: durable progress, current projections, revision references, selective delivery, and coalesced maintenance. Accuracy benefits from richer linking remain a separate hypothesis.

## Current baseline and remaining gaps

The current [multi-agent guide](../multi-agent-always-on.md) and [grounding guide](../memory-grounding-context.md) describe workspace operation/resource coordination, shared verification claims, workspace budgets, independent durable subscriptions, exact evidence roots, derived-memory invalidation, and source ACL enforcement. The earlier [multi-agent research](multi-always-on-memory.md) predates those fixes; its old missing-claim/counter/authority observations must not be treated as current defects.

Read-only inspection of the starting implementation identifies the narrower seams:

| Existing mechanism | Gap for an agent returning after sleep |
|---|---|
| [`ResumePacket`](../../src/ai_knot/always_on/models.py) and [`resume`](../../src/ai_knot/always_on/_state.py) report one intent, unresolved actions, stale basis and freshness | No composed team-memory delivery/current-context packet; resume readiness is not proof that shared-memory catch-up finished |
| [`poll`/`ack`](../../src/ai_knot/always_on/subscriptions.py) persist per-agent cursors and stable inflight deliveries, coalesce by fact, and recheck access | `ChangeBatch` exposes events and `resync_required`, but not scanned-through/head/completeness. One call scans at most 1,000 raw changes, so an empty event list can precede relevant backlog |
| `CursorExpired` detects pruned history; ACL changes can demand resync | No explicit bounded snapshot/rebase operation in that API. Blindly restarting at the current head could lose unseen changes |
| Fact/slot selectors and debounce already exist | Host still assembles wake policy, drains backlog, selects readable current facts, and decides when model context needs rebuilding |
| Basis checks protect future guarded use; pool sync suppresses inaccessible/invalid descendants | Instance-local sync delivery metadata is lost on reopen; the host needs a durable return path and must discard invalid cached context |

These are API/composition gaps inferred from source inspection, not newly reproduced failures. No old probes or benchmark scripts were run for this note.

## Four candidate mechanisms, ranked

**1. Return packet with bounded progress and explicit recovery.** Compose existing intent resume information with relevant delivery metadata and readable current fact revisions. Return a delivery token and an honest completeness indicator; distinguish “no relevant changes in this page” from “caught up.” A bounded API may require more host calls without invoking a model. On expired history, return an explicit resync path: bounded current projection plus a captured stream watermark, then replay changes after that watermark. A truncated projection cannot be acknowledged as a complete replacement. Preserve existing durable ack semantics; saving a processing receipt precedes ack. This proposal combines the useful state/knowledge separation in LangGraph with the cheap compiled-context idea in Honcho; neither source supplies the complete proposed contract.

**2. Selective wakeups over durable state.** Reuse fact/slot selectors and debounce; the host drains/coalesces changes before waking a model. Invalidated basis, unresolved actions, due waits and material selected changes are wake reasons. A wake signal is a hint to read the durable inbox, never the delivery itself. If polling load becomes material, PostgreSQL [`LISTEN`](https://www.postgresql.org/docs/16/sql-listen.html)/[`NOTIFY`](https://www.postgresql.org/docs/16/sql-notify.html) can signal availability: commit LISTEN, inspect backlog, then wait; reconnect repeats the sequence. Notifications reach current listeners and can be coalesced, so tables/cursors remain authoritative. Do not put private fact text in notification payloads. LangMem's debounce transfers; its process-local executor does not replace shared claims. No event/new due work means **zero model calls**, even if a host performs cheap SQL checks.

**3. Revision-bound context and handoff.** Carry existing evidence references with selected context, record where catch-up stopped, and rebuild a cached plan/context when those references or source permissions change. Return current state and recent transitions separately: a fact learned today may describe yesterday, and “unchanged since last seen” does not mean fresh. Keep action-time basis/freshness validation because changes can commit after packet assembly. Do not invent another evidence graph: AI Knot already has roots/dependencies and guarded action admission. The remaining work is exposing/using that information consistently when a new process resumes. A handoff transfers task references and operation identity; it grants no new authority and carries no usable old lease.

**4. Optional shared experience index.** After completion, produce one budgeted, lineage-bound team lesson and link it to task/outcome/source records; retrieve a small role/task-specific subset next time. Start with existing tags/qualifiers and recall, inspired by A-MEM/G-Memory, rather than a new graph database or one reflecting model per agent. Do not treat repeated summaries of the same observation as independent evidence. Keep this behind an experiment: linked lessons may improve selection, but may also amplify a wrong conclusion or consume more than they save. MUFFIN supports testing selective findings; it does not justify dropping durable unseen updates in favor of a recent-k window.

## Falsifiable acceptance plan

Use isolated SQLite/PostgreSQL stores, independent processes/connections and a fixed clock. These are proposed tests, **not results from this research**.

| Scenario | Reject the mechanism if… |
|---|---|
| Agent sleeps while >2,000 mixed relevant/unrelated changes arrive, including multiple revisions per fact | A bounded empty page is reported as fully caught up; a relevant final revision/control invalidation is lost; a page exceeds its explicit output bound |
| Reopen before ack, after a durable processing receipt, and after ack | Delivery/processing cannot be retried safely, or one logical agent's ack advances another's cursor |
| History is pruned; writes race with bounded snapshot recovery | Any committed change falls between snapshot and replay; a partial snapshot silently replaces the complete cache; stale token ack succeeds |
| Source is corrected/deleted or ACL is revoked before delivery, during inflight replay and before action | New packets leak revoked content, derived text remains usable, or stale evidence permits an action |
| Eight agents receive 100 rapid changes to one watched subject; then all are idle | Paid work scales with raw event count without useful decisions, or any idle model call occurs; report SQL polls and model wakes separately |
| Return/handoff contains an unknown external outcome and a live/stale lease | Another agent blindly repeats the effect, or packet delivery is mistaken for resource ownership |
| Fixed long-lived traces: baseline recall+manual drain vs packet, then optional lesson index at equal total model budget | Required-update recall or stale-decision rate worsens; lesson index fails to improve task completion/retrieval precision enough to repay its creation cost |

Report completion/coverage, missed updates, stale decisions, unnecessary wakes, model calls/tokens per useful update and p50/p95 return latency separately. Test zero idle calls and revision/ACL safety deterministically before any real-model quality study. Set workload-specific latency targets before measuring; do not convert paper benchmark gains into an AI Knot accuracy claim.
