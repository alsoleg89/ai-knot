# Task-aware selection and reusable team experience

Research cutoff/retrieval: **2026-10-27**. Starting checkout: `fcbcad5`. Read-only research; no experiments run. This continues the [shared-memory direction](2026-10-27-shared-memory-direction.md) and [roadmap](../shared-memory-roadmap.md). Reliable return, bounded recovery and saved-context review have since shipped; the earlier note's catch-up gaps describe its starting implementation, not this one. Live docs/code URLs below are mutable; dated paper versions are explicit.

## Recommendation

Add an **opt-in, model-free task working set** before changing default recall. Keep three inputs separate: the current task, explicit evidence requirements, and the requesting agent's role. First admit facts relevant to the task/requirements, then use role to choose among eligible facts within a whole-fact character budget. Return exact evidence references, covered/missing requirements and budget omissions; use existing `review_context` before reuse. Role overlap must not manufacture task coverage or grant authority.

For reusable experience, store a **conditional procedural fact grounded in observed task outcomes**, using existing SQL facts and revision lineage. A procedure and the evidence that it worked are different records. Begin with host-authored lessons and deterministic selection; model-written consolidation is a second, separately costed experiment. No new graph service, runtime or dependency is needed.

## Transferable mechanisms from primary sources

**G-Memory, v2, 2025-06-16.** The [paper](https://arxiv.org/html/2506.07398v2) separates past tasks, detailed collaboration and reusable insights, then conditions selected material on task and role. Its [official implementation](https://raw.githubusercontent.com/bingreeky/GMemory/main/mas/memory/mas_memory/GMemory.py) stores an explicit successful/failed task label, retrieves separate positive/negative examples, reranks successful trajectories with model calls, and `project_insights` uses a model to rewrite insights for a role, optionally with the current trajectory. Transfer the conditional example/outcome structure and separate role input. Do not transfer the graph stack or repeated model projection into the first slice. The evidence includes bounded embodied tasks and QA, not disconnected-worker validity, source revocation or indefinite autonomous operation.

**MUFFIN, v1, 2026-10-22.** Its [protocol](https://arxiv.org/html/2610.31355v1) gives each agent a task, role/subtask, private context and concise peer findings. Published findings are appended; an agent reads a bounded recent peer window. The prompt asks agents to verify findings and identify sources when using/rejecting them. The useful transfer is compact, attributable findings instead of full transcripts. Recent-k is not a substitute for durable missed-update delivery or requirement coverage: a critical older warning can fall out. The paper's QA/reasoning ablation finds that more findings can hurt; tool use and long-horizon tasks remain future work. Do not adopt its reported gains as AI Knot expectations.

**A-MEM, v11, 2025-10-08.** The [paper](https://arxiv.org/html/2502.12110v11) models a note with original content, timestamp, keywords, tags, contextual description and links, and evolves older representations. [Official code](https://raw.githubusercontent.com/WujiangXu/A-mem-sys/main/agentic_memory/memory_system.py) analyzes missing metadata and separately calls memory evolution; [retrieval code](https://raw.githubusercontent.com/WujiangXu/A-mem-sys/main/agentic_memory/retrievers.py) includes metadata in indexed text. Transfer bounded task/applicability descriptors into existing qualifiers/tags and test them. Generated tags are retrieval hints, not evidence or permission. The code's optional metadata analysis does not imply no model calls during the full write path. Conversation QA evidence does not establish multi-worker operational semantics.

**LangMem / Letta, current docs.** LangMem's [episodic example](https://langchain-ai.github.io/langmem/guides/extract_episodic_memories/) has observation/action/result fields: useful outcome-bearing examples, although its demonstration infers success from conversation rather than an independent tool receipt. Its [procedural-memory guide](https://langchain-ai.github.io/langmem/concepts/conceptual_guide/) can optimize system instructions from scored trajectories. Letta's [dreaming](https://docs.letta.com/configuration/memory) consolidates recent conversations after step counts or compaction, with an optional second model review. Transfer explicit outcome records and event-bounded consolidation. For this milestone, keep lessons as retrieved data instead of automatically modifying system instructions. Neither documentation supplies equal-budget evidence that a background reflection per agent improves always-on team decisions. Store concise observations, actions, result evidence and a rationale summary; full private reasoning is unnecessary.

## Smallest testable design

### Selection: task relevance first, role preference second

Use a small request value containing task query, optional role/tags, bounded explicit requirements, `top_k` and `max_chars`. Treat it as trusted host context for retrieval only. A role such as “operator” carries no read, execute or policy authority.

1. Run the existing active/readable/supported/lineage gates before matching; preserve time and topic semantics. Keep ordinary recall unchanged when the new request is absent.
2. Harvest from the task query and each explicit requirement with the existing BM25/tokenizer. Union candidates before role ranking; avoid allowing publisher-expertise narrowing to eliminate the only prerequisite. Initially use the existing authorized fact set rather than building another index. Bound the harvest and expose incompleteness if it cannot cover the request.
3. Keep original task/requirement relevance scores separate from role affinity. Use explicit metadata/tag matches as a soft preference among relevant facts; role text alone cannot admit a fact or mark a requirement covered. Unlabelled facts remain eligible. Environment/version/subject constraints supplied by the host are applicability checks, not merely score boosts.
4. Select whole facts for requirement coverage first, then bounded backfill for task utility/role fit; deterministic ties and deduplication. Never fill a role quota with irrelevant facts. Report missing requirements after the character budget, not before. Characters are not tokens: measure real prompt tokens separately during a model study.
5. Carry exact `EvidenceRef`s into saved context and feed them to `review_context`; corrected/revoked prerequisites must disappear on reopening. Current context remains data, and action-time admission still rechecks evidence and authority.

The uncertain part is whether simple role metadata adds value beyond an explicit task query. Ablate role separately; do not bundle improved requirements with role and credit the role for all gains.

### Experience: conditional lesson plus recorded outcome

Represent a small procedural projection with: applicability/task family and environment; steps or failure warning; expected result/check; observed outcome (`succeeded`, `failed`, `unknown`); outcome/source references; and optional role tags. Keep compact human-readable content plus validated string qualifiers. Store outcome evidence as retained source facts or authenticated host evidence; an action's local permit is not proof that its external effect succeeded.

Reuse `derive_fact` lineage, extending its guarded construction only as needed for bounded type/metadata. Reserve internal lineage keys so metadata cannot overwrite them. Keep unknown outcomes out of successful-example promotion. A failure supports a conditional warning, not an unconditional rule that the procedure never works. One success does not establish universal applicability. Multiple agents copying one receipt still provide one independent observation; `independent_evidence` already gives the right root-counting basis. Retrieval count records exposure, not successful reuse.

Initially require a host-provided observed outcome and concise lesson; do not automatically promote an assembled answer merely because it has coverage or multiple publishers. Preserve failure cases alongside success cases. Source correction, outcome retraction and ACL revocation must invalidate the projection through existing exact dependencies. Batch optional model consolidation only after new completed evidence, under the workspace maintenance budget; no new work means no model call.

## Falsifiable trace plan

Freeze **16 traces**: four task families (rollout recovery, queue-worker recovery, API migration, release verification) × two recipient roles (operator/reviewer) × matching/mismatching applicability. Each has four checkpoints: initial task; peer update while sleeping; handoff to a fresh process; source/outcome correction or revocation. This yields 64 selection checkpoints. Fix seeds, timestamps, raw facts, permissions, outcome receipts and task requirements before tuning; retain a held-out task/environment wording set.

Each corpus includes a verbose wrong-environment procedure, a rare-publisher prerequisite, a role-keyword distractor, an old but still relevant warning, an unsupported or revoked lesson, a copied observation, one successful example and one failed/unknown example. Label required/acceptable/forbidden evidence and the expected safe next action before running any selector.

| Comparison | Fixed controls | Falsifier / measurements |
|---|---|---|
| Existing recall vs task-only selector vs task+role selector | Same readable facts, requirement labels, candidate cap, `top_k`, e.g. 6,000-character context ceiling; zero selection model calls | Any forbidden evidence or silent false coverage fails. Report required-evidence recall, precision, omitted requirements, irrelevant characters and latency. Role must improve paired ambiguous-role cases without reducing prerequisite recall |
| Same selector with and without applicability fields | Same lessons and source data | Wrong-environment/version procedure is selected as applicable, or absent applicability is silently assumed to match |
| Durable lesson after correction/deletion/ACL change/restart | Same exact source revisions and grants on both SQL backends | Corrected/revoked lesson remains usable; source IDs leak through rejected context; independent-root count rises from copies |
| Existing facts+lessons vs optional new consolidation | Same raw evidence available to both arms; charge extraction, embeddings, projection/review and answering calls/tokens; cap total model budget | More final tasks complete only because one arm received extra data or uncounted inference; stale advice or failed/unknown-to-success promotion increases |
| Missing role, missing requirement, fact-order permutation and renamed publisher identities | Same task and permissions | Missing optional fields break baseline behavior; irrelevant role text creates coverage; arbitrary ordering changes required coverage |

For a model study, use the same model/version and prompt template, count task/role text against context and inference budgets, and score actual next decisions/task completion with independent receipts. Use paired traces and repeat stochastic runs. Pre-register a useful improvement threshold and confidence interval before paying for it; keep the feature opt-in if quality is indistinguishable or worse. Deterministic synthetic traces establish safety/selection behavior, **not** a real-model accuracy improvement.

Implement the selector and inspectable missing-evidence report first. Add durable conditional experiences next. Only add automatic reflection or richer note linking after those ablations show measurable benefit at the same total data/model budget.
